# Завдання 13. Обробник, що блокує програму (середнє)

Програма обробляє чергу завдань і має коректно завершуватися за `SIGTERM`.

```python
import signal
import sys
import threading

lock = threading.Lock()
queue = ["a", "b", "c"]

def save_state():
    with lock:
        with open("state.txt", "w") as f:
            f.write(",".join(queue))

def on_term(signum, frame):
    save_state()
    sys.exit(0)

signal.signal(signal.SIGTERM, on_term)

while queue:
    with lock:

        handle(item)
```

Відповідь:

Програма іноді зависає через те, що асинхронний сигнал SIGTERM може надійти під час виконання критичної секції коду, коли потік вже захопив блокування threading.Lock(). Обробник сигналу викликає функцію save_state(), яка намагається наново захопити той самий заблокований lock, що призводить до взаємного блокування (deadlock), оскільки обробник сигналу виконується в тому ж головному потоці[cite: 37]. Ще однією проблемою такого обробника є порушення безпеки асинхронних сигналів, якщо перервано складну зміну структур даних або несумісну операцію[cite: 39]. Виправлення полягає у тому, щоб в обробнику сигналу лише встановлювати простий прапорець (наприклад, змінювати глобальну змінну-флаг), а всю роботу зі збереження стану виконувати в безпечному місці основного циклу програми[cite: 37, 39].
