# Завдання 13. Обробник, що блокує програму (середнє)

Програма обробляє чергу завдань і має коректно завершуватися за `SIGTERM`.

```python
import signal
import sys
import threading

lock = threading.Lock()
queue = ["a", "b", "c"]

def save_state():
    with lock:
        with open("state.txt", "w") as f:
            f.write(",".join(queue))

def on_term(signum, frame):
    save_state()
    sys.exit(0)

signal.signal(signal.SIGTERM, on_term)

while queue:
    with lock:
        item = queue.pop(0)
        handle(item)
```

Відповідь:

Програма іноді зависає через те, що сигнал SIGTERM може надійти під час виконання критичної секції або під час операції з блокуванням thread.Lock(). Обробник сигналу викликає save_state(), який намагається знову захопити той самий заблокований lock, що призводить до взаємного блокування (deadlock). Ще однією проблемою такого обробника є використання в асинхронному обробнику сигналу функцій, які не є асинхронно-безпечними (наприклад, sys.exit або операції з файлами й потоками). Запропововане виправлення полягає у тому, щоб в обробнику сигналу лише встановлювати спеціальний прапорець (наприклад, atomic-змінну чи флаг виходу), а головний цикл програми періодично перевіряв його та коректно завершував роботу поза обробником.
